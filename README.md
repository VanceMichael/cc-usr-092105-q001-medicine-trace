# 回流药跨省证据归并 · 医保稽核后台

面向宜宾医保稽核场景：对包装受损、追溯码被涂改的扣押药品，核清每盒药的
初始结算机构，并把跨省就医、资金、物流、网售、扣押与办案协作线索拼成
可移送、可质证的事实链。

## 能力一览

- **六类原始来源逐字保存**：药品赋码/扫码事件、参保人就医结算、票账货款材料、
  仓库扣押登记、网络销售取证、办案协作函件；报文哈希 + 哈希链防篡改。
- **更正只能追加版本**：同业务键的勘误生成 v2/v3，旧版永久保留，更正原因必填。
- **重复上传 / 迟到数据**：重复报文只留送达痕迹不产生新版本；迟到补单按
  业务时间水位线识别并触发复评，不插队改写历史。
- **可解释风险线索**（风险提示与违法认定严格分离）：
  - `REAPPEAR-01` 同一药盒医保结算后跨省异地再现（结合网售/扣押/包装受损）
  - `REPEAT-RX-01` 同一参保人同日短间隔、跨机构/跨省重复开药
  - `COLD-01` 冷链票账与真实扫码在时段、区域、温度上的矛盾
  每条线索带规则版本、生效参数、证据版本快照、人话时间线，系统不作违法定性。
- **批量交叉比对作业**：作业前冻结数据切点；复评只追加线索版本；
  人工已排除/确认/移送的线索不被机器状态翻案。
- **多人并发研判**：修订号乐观锁，过期提交返回冲突，决定只追加、序号连续。
- **证据封存与跨省交接**：案件级清单哈希；交接前必须封存；接收方复算哈希
  并出具带完整性结论的回执，不一致如实记录、不得签收采信。
- **谱系还原**：从一条线索还原当时数据切点、每条证据的精确版本、
  全部人工决定（含所基于的修订号）、封存包与交接回执。
- **分级查看**：supervisor / investigator / viewer 案件成员制；
  公众匿名端只能核验单盒药品止于发药的合法流转摘要（脱敏，不含任何办案信息）。

## 目录

- `docs/domain.md` — 领域对象与铁律；`docs/backend.md` — 后台完整设计说明
- `contracts/domain.schema.json`、`fixtures/domain.json` — 共享领域资料
- `src/` — store / rules / services / access / api / seed / demo / server
- `tests/` — 32 个用例，覆盖存储不变量、规则、并发、封存、交接、权限、HTTP

## 快速开始

```bash
python3 -m unittest discover -s tests -v     # 全量测试
python3 -m src.demo                          # 端到端稽核故事（不落盘）
python3 -m src.server --seed --with-late --port 8080   # 启动后台
```

启动后示例（角色头由政务网关注入）：

```bash
# 公众：只核验单盒合法流转
curl http://127.0.0.1:8080/api/public/verify/BOX8102B202608200007

# 内部：触发批量比对
curl -X POST http://127.0.0.1:8080/api/batch-jobs \
  -H 'X-User-Id: zhang.jg' -H 'X-Role: investigator' -d '{}'
```

样例中的名称和编号均为虚构，不对应任何真实个人、企业或业务记录。
