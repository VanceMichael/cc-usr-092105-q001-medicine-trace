# 回流药跨省证据归并 · 稽核后台

面向宜宾医保稽核场景的可运行后台：把**药品赋码与扫码、参保人就医结算、
票账货款材料、仓库扣押登记、网络销售、办案协作**六类来源按原始报文保存，
对"外包装受损、追溯码被涂改"的扣押药品，核清每盒药最初在哪家机构结算，
并把跨省就医、资金、物流与监控线索拼成经得起移送的事实链。

纯标准库实现（Python 3.11+ / SQLite，无第三方依赖）。

## 它如何满足稽核要求

- **按原始来源保存、更正只能追加版本**：六类来源先落只读 `raw_records`
  （原文 JSON + 内容哈希），业务数据由原文派生；结算/药品/票账的更正追加
  新版本，旧版本永久保留，可回放原始报文。
- **重复上传 / 迟到数据**：同一来源相同内容按 sha256 判重，重复上传零新增；
  业务时间更早才送达的数据打 `is_late` 标记但不丢弃。
- **可解释风险线索，但不自动定性违法**：引擎只产出三类线索并附规则、阈值、
  命中输入（含原始记录号与版本）和自然语言依据，状态恒为 `open`；
  排除/移送等结论只能由持锁的人工账号写入。
  - 同一药盒在不同地区再次出现（网售/扣押上调级别）
  - 同一参保人同一天短间隔重复开药（阈值可配，默认 180 分钟）
  - 冷链材料与真实流转不符（探头温度超区间 / 真实环节不在声称冷链时段）
- **批量交叉比对**：`rules.run_all` 可全量或按药盒/参保人范围增量比对，
  按业务身份去重，数据更正后重跑不重复造线索。
- **多人并发研判**：线索显式加锁（令牌 + TTL），同一时刻只允许一人下结论，
  未持锁的决定被拒绝（已用 6 线程实测：1 人持锁、5 人冲突）。
- **证据封存与交接回执**：封存固化当时全部数据版本与原始记录哈希（哈希链），
  封存后案件冻结；移送必须引用封存，接收方回执追加不改写。
- **一条线索还原全程**：从线索可还原命中依据 → 各次人工决定及其采用的数据
  版本 → 封存清单哈希 → 交接回执；`integrity` 可检出任何篡改。
- **分级查看**：案件人员看完整档案与证据链；普通查询者只能核验单盒药品的
  合法流转摘要（无案件、参保人、扣押地、网售平台等敏感字段），所有访问留痕。

## 目录

```
src/audit/            后台实现（schema / 入库 / 规则 / 案件 / 分级查询）
scripts/demo_yibin.py 宜宾跨省回流药端到端演示（虚构数据）
scripts/audit_cli.py  命令行
tests/test_audit.py   20 项端到端测试
docs/domain.md        领域对象与规则口径
docs/architecture.md  架构、数据模型、并发与分级可见性
contracts/ fixtures/  公开领域资料与样例
```

## 运行

```bash
# 端到端演示（六类来源 → 三类线索 → 并发研判 → 封存 → 交接回执 → 分级查看）
PYTHONPATH=. python3 scripts/demo_yibin.py

# 测试
python3 -m unittest discover -s tests -v

# 命令行
export AUDIT_DB=/tmp/audit.db
python3 scripts/audit_cli.py init
python3 scripts/audit_cli.py rules
python3 scripts/audit_cli.py public-verify 8115-M1-0001
```

样例中的名称、编号均为虚构，仅用于说明字段关系，不对应任何真实个人、企业或
业务记录。
