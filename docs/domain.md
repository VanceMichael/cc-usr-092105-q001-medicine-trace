# 领域约定

本项目面向"回流药跨省证据归并"稽核后台，保存药品追溯、医保结算与跨部门
核查所需的共享资料与可运行实现。

## 核心对象

- 药品主档与赋码（一药一码，码面涂改/包装受损时以全国平台历史记录为准）
- 药品追溯/扫码事件（生产、仓储、配送、入院、配发、结算、二次销售、扣押）
- 参保人与就医结算记录（含跨省异地就医直接结算、最初结算机构）
- 流通凭证（发票、账册、随货同行、冷链温控、资金支付）
- 仓库扣押登记（外包装状态、辨认/还原码、数量）
- 网络销售记录（平台、店铺、发货地、买家地区）
- 办案协作（跨省协查、物流、监控、资金）
- 核查线索、人工研判决定、案件、证据封存、交接回执、访问审计

## 必须遵守的规则

1. 历史事件不得被更正覆盖——原始报文只读（WORM），业务事实的更正只能追加
   新版本，旧版本永久保留并可回放。
2. 风险提示与违法认定必须分离——规则引擎只产出带依据的线索（恒为 `open`），
   `dismissed`/`confirmed_transfer` 等结论只能由持锁的人工账号写入。
3. 公众查询不得暴露案件和参保人敏感信息——普通查询者只能核验单盒药品的
   合法流转摘要（无案件、线索、扣押地、网售平台、参保人信息）。
4. 全程留痕——入库、研判、封存、交接、查询（含公众查询）均写审计日志。
5. 证据封存后冻结——封存生成版本清单与哈希链，封存案件不再接受研判或归并；
   移送必须引用封存，接收方在同一交接记录上追加回执。

## 风险线索口径（阈值可按办案口径配置）

| 线索类型 | 触发口径 | 级别 |
| --- | --- | --- |
| `cross_region_reappear` | 药盒在某机构结算出店后，又在结算地以外地区露面（网售/扣押上调级别） | medium/high |
| `repeat_prescription` | 同一参保人同一自然日内，相邻两次开药间隔 ≤ 阈值（默认 180 分钟） | medium |
| `cold_chain_mismatch` | 探头实际温度超出材料声称区间，或真实环节时间落在声称冷链时段之外 | high |

所有线索均保存：规则名、阈值、命中输入（含原始记录号与数据版本）、
自然语言推理说明、证据快照哈希与业务身份去重键。

样例中的名称和编号仅用于说明字段关系，不能对应到现实中的个人、企业或业务记录。
